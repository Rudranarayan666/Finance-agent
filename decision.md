# Architectural Decision Record (ADR) & Design Decisions

## 🏛️ FinanceAgent: Enterprise Financial Report Analyzer

This document records the foundational architectural decisions, design rationales, trade-offs, and technical standards governing the **FinanceAgent** platform.

---

## 1. Architectural Principles & Strategy

### 1.1 Deterministic Grounding Boundary vs. LLM Non-Determinism
* **Decision**: All financial figures, citations, arithmetic calculations (margins, YoY changes), and conflict reconciliations must be executed **strictly outside the LLM** in deterministic Python algorithms.
* **Context**: Traditional LLMs suffer from numerical hallucinations, compounding calculation errors, and phantom page citations. In financial analysis, even minor numerical hallucinations can cause catastrophic misallocations of capital or regulatory breaches.
* **Consequences**:
  * The LLM acts solely as a candidate extractor and natural language synthesis engine.
  * Every extracted candidate is validated using verbatim substring matching against raw document text.
  * Calculations (e.g. `(Gross Profit / Revenue) * 100`) are computed by an explicit `ArithmeticEngine`, not generated by an LLM prompt.

### 1.2 Multi-Agent Specialization with LangGraph Supervisor
* **Decision**: Adopt a multi-agent orchestration architecture structured with LangGraph, supervised by an orchestrator node that coordinates specialized sub-agents:
  1. **Section Locator Agent**: Calculates statement density heuristics to locate primary financial tables in filings of 250+ pages.
  2. **Financial Extraction Agent**: Extracts core balance sheet, income statement, and cash flow items.
  3. **Guidance & Outlook Agent**: Identifies forward-looking disclosures and capital expenditure guidance.
  4. **Risk Factors Agent**: Extracts critical regulatory, liquidity, and operational risk disclosures.
  5. **Grounded Interpretation Agent**: Synthesizes verified disclosures into executive summaries.
* **Rationale**: Monolithic prompts degrade rapidly when analyzing complex 100–250+ page SEC filings (10-K, 10-Q) and institutional annual reports. Breaking responsibilities into focused agents with targeted validation schemas guarantees audit-grade precision.

## 2. Security, Cryptography & Compliance

### 2.1 Tamper-Proof Cryptographic Blockchain Seals (SHA-256)
* **Decision**: Every uploaded financial filing is fingerprinted at byte level using SHA-256 to create an immutable cryptographic block seal (`VERIFIED_IMMUTABLE`) stored with timestamp and provenance metadata.
* **Rationale**: Institutional compliance (SOC2, SEC audit standards) requires non-repudiation and verification that documents analyzed in the platform have not been altered or tampered with post-upload.

### 2.2 Active-Script PDF Malware Neutralization
* **Decision**: Implement a two-step pre-ingestion security pipeline:
  1. Validate `%PDF-1.x` magic bytes to block masqueraded binary files.
  2. Scan and neutralize PDF active script vectors (`/JavaScript`, `/Launch`, `/EmbeddedFiles`, `/URI`) before passing bytes to parsers.
* **Rationale**: Corporate finance servers and analyst environments are prime targets for malicious payloads concealed within mock earnings PDF attachments.

### 2.3 Organization-Scoped Multi-Tenant Isolation & RBAC
* **Decision**: All database models, queries, document repositories, and audit logs are partitioned by `organization_id`. Role-based access control enforces three tiers:
  * **Admin**: User provisioning, teammate invitations, organization-wide configuration, filterable audit log inspection.
  * **Analyst**: Document upload, multi-agent analysis triggering, interactive visualization inspection, RAG Q&A.
  * **Viewer**: Read-only access to organization documents, pre-computed analysis scorecards, and audit receipts.
* **Rationale**: Prevents cross-departmental or cross-tenant data leaks of sensitive pre-earnings releases and confidential corporate filings.

## 3. Retrieval-Augmented Generation (RAG) & Explainable AI (XAI)

### 3.1 Document-Scoped RAG with Financial Synonym Expansion
* **Decision**: Scope RAG queries strictly to individual documents using BM25 token retrieval augmented with domain-specific synonym expansion (e.g., mapping `PAT` to `Profit After Tax` and `Net Profit`, `Topline` to `Revenue`).
* **Rationale**: Cross-document vector pollution causes models to blend numbers across different quarters or distinct corporate entities. Financial jargon varies across US GAAP, IFRS, and regional reporting conventions.

### 3.2 Recharts SHAP Waterfall Attribution
* **Decision**: Render profitability drivers using an interactive Recharts SHAP-style waterfall chart rather than opaque progress bars or static metric lists.
* **Rationale**: Institutional stakeholders require transparent attribution of what specifically drove net profit expansion or contraction (e.g., revenue growth vs. SG&A headwinds vs. tax provisions).

## 4. User Experience & Frontend Architecture

### 4.1 Hybrid Responsive Design & Dedicated Mobile Navigation
* **Decision**: Support full-scale dual experience:
  * **Desktop**: Three-column analytics console, Recharts waterfall, and interactive split-screen document viewer.
  * **Mobile / Tablet (375px+)**: 2-column scorecard grid, responsive drawer menu, pinned bottom navigation bar, and sticky chat input.
* **Rationale**: Enable executives and mobile portfolio managers to review quarterly scorecards and query documents on-the-go without degraded UI usability.

### 4.2 Three.js Visual Containment
* **Decision**: Confine Three.js 3D particle constellation strictly behind the hero section of the landing page, automatically disabling it on mobile viewports (`< 768px`) or low-power devices.
* **Rationale**: Prevents canvas overlay bleed, reduces background GPU overhead, and maintains a high-contrast enterprise design aesthetic across analytics tables and cards.

## 5. Technology Stack Summary

| Layer | Selected Technology | Primary Rationale |
| :--- | :--- | :--- |
| **Backend Framework** | FastAPI (Python 3.11+) | Async I/O, native Pydantic validation, OpenAPI compliance |

| **Styling** | Tailwind CSS & Vanilla CSS | Modular utility tokens, dark-mode styling, glassmorphism |
| **Data Visualization** | Recharts & Lucide React | Interactive SVG charts, responsive waterfall visualization |
| **Testing & Quality** | Pytest (14/14 automated tests) | End-to-end endpoint validation, auth checks, and arithmetic tests |
